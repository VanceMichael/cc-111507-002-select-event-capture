# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。
  - `raw`：只领取入口文件并记录元信息，状态为 received。
  - `structured`：运单对象查询收件。流式读取来源事件流，按跨帧 CSV 语义整理运单记录，只投影授权字段 `id`、`note`。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件记录（含证据与问题，用于诊断）。结构化收件未完成时，这些视图中的 `records` 为空，另以 `published: false` 和 `recordsWithheld` 表明本地保留但未发布的记录数；完整记录仍保存在 DATA_DIR 的收件文件中供审计。
- `GET /v1/receipts/{id}/records`：读取已确认完成的查询结果。结构化收件在 state 不是 complete 时返回 409，不发布记录清单。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化收件只有在收到合法 `End` 事件且没有致命帧/CSV 问题时才写 complete。连接关闭、缺少 `End`、prelude/message CRC 失败、帧截断、来源 error 事件都不能发布成完整清单；这类收件分别是 partial（已取得部分记录）或 rejected（无法取得记录）。`GET /v1/receipts/{id}/records` 对未完成的结构化收件返回 409。

`coverage` 中来源处理的统计与本地实际接收量分列：`sourceStats` 保存来源 Stats 事件的 BytesScanned/BytesProcessed/BytesReturned，`receivedBytes`/`downloadedBytes` 是本服务实际从来源连接读取的字节数，`recordsBytes` 是 Records payload 的总字节数。`recordsFrames` 与每条记录的 `frames` 给出记录对应的来源帧区间，记录可横跨多帧。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 每个数据记录一条，`id`/`note` 为 CSV 列名，`note` 保留字段内换行；每条记录附 `frames` 来源帧区间 `[起始帧, 结束帧]`。其他 CSV 列不投影、不发布，`coverage.omittedColumnCount` 仅给出被省略的列数。
